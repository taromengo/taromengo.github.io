Local inference stack

Runs hybrid search and simple coding tasks on open-weight models

Work that does not need a frontier model runs on company hardware, with no API fee: hybrid search for production apps, and simple coding tasks.

The problem

Every embedding, reranking and assistant call went to paid APIs. Each call cost money that could have been saved.

Coding and developer tooling on frontier APIs was expensive too, even for simple work a smaller model can handle.

What I owned

I owned the local inference setup end to end, from choosing models to serving them, designing the endpoint and connecting production apps.

The main user is the Agentic RAG assistant, which has its own case study.

How it works

One endpoint for every app

llama-swap puts every local model behind one OpenAI-compatible endpoint on a single port, with a separate route for each kind of call: completions, embeddings and reranking.

Models start on demand

vLLM serves open-weight models in Podman containers, and llama-swap starts those containers on demand.

Warm-up hides the cold start

Loading a model from cold takes 40–60 seconds, too long for someone waiting on their first question. To improve the user experience, I implemented a warm-up where the app sends a headless warm-up request. llama-swap loads the embedding model and reranker before the first question arrives.

Decisions

Local or API, per workload

Embedding and reranking use small models that run quickly on one GPU, and simple coding tasks and developer tooling can tolerate a slower local model. The RAG assistant’s answer generation and its LLM judge stay on an external API, because users wait on them and they need a stronger model.

Trade-off. The answers and the judge still carry a per-call API fee. In return, the users get lower latency with higher model intelligence.

Simple coding work goes local

Coding and developer tooling adds up on APIs, so I decided to use local models for simple, small edits.
